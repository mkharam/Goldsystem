# متابعة الصيانة — Repair Tracker

تطبيق مستقل لاستلام قطع الصيانة ومتابعتها وتسليمها، بقاعدة بيانات Supabase خاصة به،
عربي بالكامل (RTL) ومصمَّم للهاتف أولاً.

يتكامل مع نظام المخزون (`jewel-sight-manager`) عبر واجهة HTTP واحدة فقط — ولا يملك
وصولاً مباشراً لقاعدة بياناته. **وعند تعذّر الوصول إليها يبقى التطبيق عاملاً بالكامل
بالإدخال اليدوي.**

## الميزات

- **تذاكر صيانة** برقم متسلسل لكل فرع (`R-26-01-0001`) وصور عند الاستلام
- **تعبئة تلقائية** للوزن والعيار بمسح كود القطعة من المخزون، وبحث الزبون بالهاتف
- **إيصال بـ QR** يُطبع من المتصفح، يفتح صفحة تتبّع عامة بلا تسجيل دخول
- **مسار حالات** مضبوط: مستلمة ← قيد التنفيذ ← جاهزة ← مسلّمة (أو ملغاة)
- **زر إبلاغ عبر واتساب** برسالة جاهزة، مع تسجيل من أبلغ ومتى
- **فحص الوزن عند التسليم** — يقارن بوزن الاستلام ويمنع الإغلاق عند تجاوز المسموح
  إلا بتأكيد صريح وسبب مكتوب
- **لوحة المتأخّرات** لما فات موعده وما زال مفتوحاً

## التشغيل

```bash
npm install
cp .env.example .env.local   # ثم املأ القيم
npm run dev
```

### قاعدة البيانات

أنشئ مشروع Supabase **جديداً خاصاً بهذا التطبيق** (لا تستخدم مشروع المخزون)، ثم طبّق
الهجرة:

```bash
supabase link --project-ref <ref>
supabase db push
```

الهجرة تُنشئ الجداول وحاوية الصور `repair-photos` وتقفل RLS بالكامل.

### متغيّرات البيئة

| المتغيّر | الغرض |
| --- | --- |
| `SUPABASE_URL` | مشروع Supabase الخاص بالصيانة |
| `SUPABASE_SERVICE_ROLE_KEY` | مفتاح الخدمة — على الخادم فقط |
| `SESSION_SECRET` | سرّ توقيع جلسات الموظفين (`openssl rand -hex 32`) |
| `INVENTORY_API_URL` | عنوان دالة `repair-api` في المخزون (اختياري) |
| `INVENTORY_API_KEY` | نفس قيمة `REPAIR_API_KEY` في المخزون (اختياري) |
| `NEXT_PUBLIC_APP_URL` | العنوان العام — يُبنى منه رابط التتبّع في رمز QR |

> لا يوجد أي مفتاح بادئته `NEXT_PUBLIC_` عدا عنوان التطبيق، لأن **المتصفح لا يتصل
> بـ Supabase إطلاقاً**: كل قراءة وكتابة تمرّ عبر خادم Next.js بعد التحقق من الجلسة.

## التكامل مع المخزون

العقد الكامل موثّق في `jewel-sight-manager/docs/repair-api.md`. باختصار، تطبيق الصيانة
يستدعي دالة `repair-api` بترويسة `x-api-key` للحصول على: تسجيل دخول الموظف، الفروع،
بحث الزبون بالهاتف، وبحث القطعة بالكود.

لتفعيله على جهة المخزون:

```bash
# داخل مستودع jewel-sight-manager
supabase secrets set REPAIR_API_KEY="$(openssl rand -hex 32)"
supabase functions deploy repair-api
```

ثم ضع المفتاح نفسه في `INVENTORY_API_KEY` هنا.

### السلوك عند انقطاع المخزون

| الوظيفة | مع المخزون | بدونه |
| --- | --- | --- |
| دخول الموظف | تحقّق من حساب المخزون | تحقّق محلي لمن سبق أن دخل مرة |
| بحث الزبون | محلي + المخزون | محلي فقط، وإلا إدخال يدوي |
| بحث القطعة بالكود | تعبئة تلقائية | إدخال يدوي للوزن والعيار |
| الفروع | مزامنة عند الدخول | آخر نسخة محفوظة |
| كل ما تبقّى | يعمل | يعمل |

مهلة كل استدعاء ٦ ثوانٍ، ولا يرمي عميل المخزون استثناءً أبداً — أي فشل يتحوّل بصمت
إلى الإدخال اليدوي، مع شريط في أعلى الشاشة يخبر الموظف أن المخزون غير متصل.

## البنية

```
src/
  app/
    login/              دخول الموظف
    page.tsx            لوحة المتأخّرات والإحصاءات
    tickets/            القائمة، الاستلام، التفاصيل، الإيصال
    track/[token]/      صفحة التتبّع العامة (بلا دخول)
    api/lookup/         بحث الزبون والقطعة أثناء الكتابة
    actions/            إجراءات الخادم (إنشاء، انتقال حالة، صور، إشعار)
  lib/
    inventory.ts        عميل واجهة المخزون — لا يفشل أبداً
    tickets.ts          استعلامات التذاكر، الانتقالات، فحص الوزن
    customers.ts        بحث الزبون ودمجه بين المحلي والمخزون
    auth.ts             الدخول مع الاحتياطي المحلي، مزامنة الفروع
    session.ts          جلسة موقّعة في كوكي + تجزئة كلمة المرور
    db.ts               عميل Supabase الوحيد (service_role، خادم فقط)
supabase/migrations/    مخطط قاعدة البيانات
```

## الإعدادات

تُضبط من جدول `settings`:

| المفتاح | الافتراضي | المعنى |
| --- | --- | --- |
| `weight_tolerance_grams` | `0.05` | الفرق المسموح بين وزن الاستلام والتسليم |
| `default_turnaround_days` | `3` | موعد التسليم الافتراضي عند فتح التذكرة |
| `shop_name` | `مجوهرات` | الاسم على الإيصال وصفحة التتبّع |
| `receipt_footer` | … | نص أسفل الإيصال |
